# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 3.1.x   | :white_check_mark: |
| < 3.1   | :x:                |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

If you discover a security vulnerability in IoT Hunter itself (not in a device it scans), please report it privately to the maintainer:

- **Maintainer / Developer:** Harsh Saini
- **Email:** cyber.h4rsh@zohomail.in
- **Organization:** MR Cyber Pulse

For project or collaboration queries, you may also reach out to:

- **Manager:** Prachi Sharma
- **Email:** manager.prachi@zohomail.in

Please include in your report:

- Type of issue (e.g., command injection, path traversal, insecure defaults)
- Full paths of the source file(s) related to the issue
- Step-by-step reproduction instructions
- Impact assessment
- Any suggested fix, if available

You can expect an acknowledgement within **7 days**. We will keep you informed of the progress and coordinate disclosure timing with you.

## Out of Scope

The following are **not** considered vulnerabilities in IoT Hunter:

- Findings about third-party devices or networks produced by the tool during an authorized scan
- Inaccurate banners, CVE false positives, or version-string mismatches (these are documented limitations)
- Missing optional dependencies (Npcap, libpcap) on the operator's system

## Safe Harbor

We support safe harbor for security researchers who:

- Make a good-faith effort to avoid privacy violations, data destruction, and service interruption
- Only interact with accounts they own or have explicit permission to access
- Report findings privately and give us reasonable time to fix before disclosure
