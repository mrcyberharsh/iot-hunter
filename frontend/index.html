MR CYBER PULSE · Defensive security

IoT Hunter

A defensive IoT security and network reconnaissance toolkit for discovering devices, understanding exposed services, and reviewing risk signals on networks you are authorized to assess.

Web API v4.0.0 CLI v3.1 Python 3.11+ Local SQLite storage
GitHub project Full README API documentation

Core capabilities

Device discovery

Finds devices on authorized private IPv4 subnets, up to /24 in scope.

Service fingerprinting

Collects service banners and vendor/OUI hints to help identify connected equipment.

CVE references

Checks observed service and version details against known vulnerability references; findings need human verification.

Protocol audit

Highlights observed protocol exposure for defensive review.

Drift snapshots

Tracks inventory changes using a bounded history of recent snapshots.

Reports

Creates PDF and JSON output for assessment results.

Safe and authorized use

  • Scan only networks and devices you own or have explicit permission to assess.
  • Discovery is scoped to private IPv4 ranges; keep each scan at /24 or narrower.
  • IoT Hunter is for defensive inventory and review. It does not brute-force credentials or exploit devices.
  • Risk labels are local heuristics, not CVSS scores or proof that a device is exploitable.
  • Review generated reports before sharing; redaction cannot guarantee removal of every sensitive value.

Firmware analysis safeguards

  • Firmware inputs are bounded to 256 MiB.
  • Archive processing is limited by entry count, per-file size, and aggregate extracted size.
  • Optional external extractors run with time and storage limits; unsupported isolation means the extractor is not run.
  • String and file output is capped to keep analysis resource use predictable.

These limits reduce resource-exhaustion risk; they are not a guarantee that every firmware format can be analyzed.

Platform and integrations

  • Web dashboard and FastAPI backend, with an API bearer-token authentication flow.
  • Command-line and Tkinter interfaces are also included in the project.
  • Docker deployment and local SQLite persistence are supported.
  • Use the README for installation, configuration, and deployment instructions; never share the configured admin secret.

Current dashboard scope

  • Inventory and risk summaries are based on data returned by the current backend.
  • Risk is a heuristic view; CVE references should be confirmed against the device and software actually present.
  • Historical dashboard trends, alert history, and Telegram message delivery are not currently provided by the backend.
  • TLS hygiene checks are documented as planned work, not an available feature.
